# Plan: Implement CI Checks (issue #1)

## Goal
Add the standard test + linting gates an Expo / React Native app needs so every PR
proves the mobile client is correct before merge. Closes #1.

## Root cause (verified)
The repo currently has **no** quality gates:
- No test runner configured (no `jest`, no `jest-expo`, no `@testing-library/react-native`).
- No ESLint config / `expo lint` not wired into a script.
- No `.github/workflows/ci.yml`.
- `App.tsx` calls `useEveAgent` directly and is not isolated behind a testable
  component, so it cannot be unit/UI tested without mocking.

Verified by inspecting the scaffold: `package.json` has only `expo` / `react` /
`react-native` + `eve`; `tests/` does not exist; `.github/` does not exist.

## Intended fix
Introduce four hermetic, locally-runnable checks plus a CI workflow:
1. **Lint/typecheck** — `tsc --noEmit` + ESLint via `expo lint`.
2. **Unit** — Jest (`jest-expo` preset) + React Native Testing Library.
3. **UI** — component tests (RNTL + Jest) rendering the chat screen.
4. **E2E** — Maestro flows under `maestro/` (launch + send-message happy path).
5. **CI** — `.github/workflows/ci.yml` triggers on `pull_request` (pre-merge gate) **and**
   `push` to `main` (post-merge re-verification of the merged result). Lint + typecheck +
   unit/UI on every PR; E2E job on a macOS runner (needs a built dev client).
   **Merge gating (out-of-code, admin):** enforce "Require status checks to pass before
   merging" on `main` via a branch ruleset (or classic branch protection) selecting the
   CI job statuses. This blocks merge until green; the post-merge `push` run re-verifies
   `main` and turns it red if something breaks, blocking the next PR.

`eve/react`'s `useEveAgent` will be **mocked** in unit/UI tests (no network in CI).
To make the UI testable, extract the chat screen into a `ChatScreen` component
(keep `App.tsx` as the entry that renders it).

## Decisions (ADRs to write in this change)
- **Maestro over Detox for E2E** — lower friction, author flows without native
  compilation; Detox remains the option if full native grey-box E2E is later required.
- **Mock `useEveAgent` in tests** — keeps the suite hermetic and fast (no Eve server
  in CI); only the component rendering/interaction is under test.

## Files likely to change
- `package.json` (scripts + devDeps: jest, jest-expo, @testing-library/react-native,
  eslint, prettier, maestro CLI)
- `jest.config.js`, `.eslintrc.js`, `.prettierrc`
- `app/ChatScreen.tsx` (extracted), `App.tsx` (renders ChatScreen)
- `tests/` (unit + UI tests)
- `maestro/` (flows + config)
- `.github/workflows/ci.yml`
- `README.md` (document check commands)

## Validation
- `npm run lint` → 0 errors
- `npm test` (jest) → all green, no network
- `maestro test maestro/flows/smoke.yaml` runs against a dev build
- CI workflow green on the PR **and** on the post-merge `main` run

## Risks / open questions
- **E2E in CI** needs a macOS runner + a built dev client (Xcode / `eas build`). The
  job will be defined but may require EAS secrets; documented as a follow-up to fully wire.
- `expo lint` may prompt to install a config on first run; pin the config explicitly.
- Mocking `useEveAgent`: `jest.mock('eve/react')` returning a controllable snapshot.
- Required status checks must reference the CI job exact `name:`; keep job names stable so the
  branch ruleset keeps matching them.
